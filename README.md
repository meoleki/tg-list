# Списки — Telegram Mini App

Мини-приложение для списков дел и покупок: несколько списков, галочки, количество для покупок,
хранение в облаке Telegram (синхронизация между вашими устройствами) и шаринг с людьми.

Всё это — один файл `index.html` без сборки и без сервера, поэтому идеально ложится на GitHub Pages.

---

## Что умеет

- Несколько списков двух типов: **Покупки** и **Дела**.
- Для покупок работает синтаксис количества: напишите `Молоко 2` → получится «Молоко ×2».
- Отметка выполненного, автоматическая группировка «Готово» внизу.
- **Хранение:** внутри Telegram — облако Telegram (`CloudStorage`, синхронизируется между вашими
  устройствами); в обычном браузере — `localStorage`.
- **Шаринг двумя способами:**
  1. **Копией-сообщением** — работает всегда, без настройки. Список уходит выбранному человеку
     текстом в Telegram.
  2. **Живой общий список** — правки видны у всех в реальном времени. Требует бесплатный Firebase
     (см. раздел ниже). Фронтенд при этом остаётся на GitHub Pages.

> Почему живой шаринг требует Firebase: GitHub Pages отдаёт только статические файлы и не может
> хранить общие данные. Чтобы правки одного человека видел другой, нужна общая база данных.
> Firebase Realtime Database вызывается прямо из браузера, поэтому сервер поднимать не нужно.

## Шаг 1. Выложить на GitHub Pages

1. Создайте репозиторий на GitHub (например, `spiski`). Можно публичный.
2. Загрузите в корень репозитория файл **`index.html`** (кнопка **Add file → Upload files**,
   либо через git). Важно, чтобы файл лежал именно в корне и назывался `index.html`.
3. Откройте **Settings → Pages**.
4. В блоке **Build and deployment → Source** выберите **Deploy from a branch**.
5. Branch: **main**, папка: **/ (root)**. Нажмите **Save**.
6. Подождите 1–2 минуты. Вверху страницы Pages появится адрес вида:
   ```
   https://ВАШ_ЛОГИН.github.io/spiski/
   ```
   GitHub Pages автоматически даёт HTTPS — а это обязательное требование Telegram.

Проверьте, что ссылка открывается в браузере и показывает приложение.

---

## Шаг 2. Создать бота

1. В Telegram откройте **@BotFather**.
2. Отправьте **/newbot**, задайте имя и username (username должен заканчиваться на `bot`).
3. Сохраните токен, который выдаст BotFather (пригодится для расширенных сценариев; для самого
   приложения он не нужен).

---

## Шаг 3. Привязать мини-апп

Есть два способа — выберите любой (или оба).

### Способ A. Кнопка меню (проще всего)

1. В **@BotFather** отправьте **/setmenubutton**.
2. Выберите вашего бота.
3. Вставьте URL с GitHub Pages: `https://ВАШ_ЛОГИН.github.io/spiski/`
4. Задайте подпись кнопки, например «Открыть списки».

Теперь у любого, кто откроет диалог с ботом, появится кнопка запуска приложения.

### Способ B. Отдельное приложение со ссылкой (нужно для шаринга по ссылке)

1. В **@BotFather** отправьте **/newapp** и выберите бота.
2. Заполните название, описание, картинку.
3. В поле Web App URL вставьте адрес GitHub Pages.
4. Задайте короткое имя (short name), например `list`.

Приложение будет открываться по ссылке `https://t.me/ВашБот/list`.
Именно эту ссылку впишите в `index.html` в константу `BOT_APP_LINK`, чтобы работал шаринг
общих списков по ссылке (иначе людям придётся вводить код вручную — тоже работает).

```js
const BOT_APP_LINK = "https://t.me/ВашБот/list";
```

## Шаг 4 (опционально). Живой общий список через Firebase

Без этого шага приложение полностью рабочее — просто шаринг идёт копией-сообщением.
Включите Firebase, если хотите редактировать списки совместно в реальном времени.

1. Зайдите на <https://console.firebase.google.com>, создайте проект (бесплатный тариф Spark).
2. В меню слева: **Build → Realtime Database → Create Database**. Выберите регион,
   запустите в **test mode** (правила ниже поменяем).
3. Откройте **Project settings (шестерёнка) → General → Your apps → Web (`</>`)**,
   зарегистрируйте веб-приложение и скопируйте объект `firebaseConfig`.
4. Вставьте его в `index.html` в константу `FIREBASE_CONFIG` (обязателен `databaseURL`):

   ```js
   const FIREBASE_CONFIG = {
     apiKey: "…",
     authDomain: "ВАШ-ПРОЕКТ.firebaseapp.com",
     databaseURL: "https://ВАШ-ПРОЕКТ-default-rtdb.firebaseio.com",
     projectId: "ВАШ-ПРОЕКТ",
   };
   ```

5. Задайте правила базы (**Realtime Database → Rules**). Простой рабочий вариант —
   доступ к общим спискам только по знанию их кода (кто получил код/ссылку — тот и редактирует):

   ```json
   {
     "rules": {
       "shared": {
         "$id": { ".read": true, ".write": true }
       }
     }
   }
   ```

6. Снова залейте обновлённый `index.html` в репозиторий. Готово: в окне «Поделиться» появится
   кнопка **«Сделать общим»**, а на главном экране — **«Присоединиться по коду»**.

> Про безопасность: ключ Firebase в клиентском коде — это нормально, он не секретный. Модель
> доступа здесь «у кого есть код — тот может редактировать» (как ссылка на общий документ).
> Если нужен строгий доступ пофамильно и защита от посторонних, знающих код, потребуется
> серверная проверка личности Telegram (валидация `initData` ботовым токеном) и Firebase Auth —
> это уже отдельный небольшой бэкенд.

---

## Обновление приложения

Просто перезалейте `index.html` в репозиторий — GitHub Pages подхватит изменения за минуту.
Если в Telegram осталась старая версия, помогает перезапуск приложения (закрыть/открыть) —
Telegram кеширует мини-аппы.

## Локальная проверка

Откройте `index.html` в браузере (или запустите `python3 -m http.server` в папке и зайдите на
`http://localhost:8000`). Вне Telegram данные хранятся в `localStorage`, тема — системная.
